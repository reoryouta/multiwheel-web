# Multiwheel — официальный сайт

Основа сайта для презентации и распространения Multiwheel — приложения для Windows, написанного на C#. Приложение открывает контекстное радиальное меню горячей клавишей и предоставляет действия для текущей активной программы.

На этом этапе реализованы главный экран (Hero) и адаптивная шапка в тёмной теме. Hero содержит заголовок, описание, статус «Скоро» и интерактивную демонстрацию радиального меню с профилями Windows, Figma, VS Code и Photoshop. Профили являются концептуальными примерами и не заявляют о реализованной поддержке этих приложений. Демонстрация показывает условные действия и не выполняет команды. В шапке находятся временный логотип, обозначения будущих разделов, переключатель языков и недоступная кнопка скачивания с пояснением. На мобильных устройствах содержимое шапки открывается кнопкой меню. Остальные секции и распространение установщика будут добавлены отдельно. Backend и база данных не используются.

## Что нужно для работы

- Node.js и npm. Требование Vite 8: Node.js `^20.19.0 || >=22.12.0`.
- Git — для ведения истории изменений, если вы будете использовать Git-репозиторий.

Проект создан на Node.js 26.13.0 и npm 11.20.0. Для новой установки Node.js можно выбрать актуальную LTS-версию, подходящую под требование выше. Глобально устанавливать Vite, TypeScript и другие пакеты не нужно: они находятся в зависимостях проекта.

## Запуск

Откройте терминал в папке проекта:

```powershell
npm ci
npm run dev
```

`npm ci` устанавливает версии из `package-lock.json`. Если зависимости уже установлены, достаточно `npm run dev`.

Откройте адрес, который напечатает Vite, обычно `http://localhost:5173`. Изменения исходников автоматически появляются в браузере. Остановка сервера: `Ctrl+C` в терминале.

## Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запустить сервер для разработки. |
| `npm run build` | Проверить TypeScript и собрать готовые файлы в `dist/`. |
| `npm run preview` | Локально посмотреть результат сборки, обычно на `http://localhost:4173`. Сначала выполните сборку. Это не сервер для публикации. |
| `npm run lint` | Проверить код линтером Oxlint из стандартного шаблона Vite. |

## Технологии

- **React 19.3.1** — компоненты интерфейса.
- **TypeScript 7.0.2** — проверка типов и подсказки в редакторе; включён строгий режим.
- **Vite 8.3.8** — запуск разработки и сборка.
- **Tailwind CSS 4.3.5** — стили через классы в JSX; подключён официальным плагином `@tailwindcss/vite`.
- **Motion 14.14.0** — короткое появление содержимого. Настройка браузера «уменьшить движение» учитывается.
- **Lucide React 1.73.0** — иконка выбора языка.
- **i18next 27.1.2 / react-i18next 18.0.1** — хранение переводов и их использование в компонентах.

Точные версии прямых зависимостей указаны в `package.json`, полное дерево зависимостей зафиксировано в `package-lock.json`. Оба файла нужно хранить в Git. Для осознанного обновления пакета используйте `npm install --save-exact имя-пакета@версия`, затем проверьте проект.

## Структура

```text
src/
  app/
    App.tsx                 # Подключает шапку и содержимое страницы
  components/
    Header.tsx              # Логотип, будущая навигация, языки, скачивание
    HeroSection.tsx         # Главный экран, тексты и анимация появления
    LanguageSwitcher.tsx    # Кнопки RU / EN
    WheelPreview.tsx        # Выбранный профиль, переключатель и переход между профилями
  features/
    wheel/
      wheelActions.ts       # Тип WheelAction и исходные действия Windows
      wheelProfiles.ts      # Тип WheelProfile и конфигурации профилей
      ProfileSwitcher.tsx   # Компактные кнопки выбора профиля
      ProfileWheel.tsx      # Переводы, состояние взаимодействия и плавный переход
      wheelGeometry.ts      # Размеры колеса и расчёт SVG-секторов
      useWheelInteraction.ts # Наведение, нажатия, фокус и клавиатура
      WheelView.tsx         # SVG и анимация без логики выбора
  pages/
    HomePage.tsx            # Подключает секции главной страницы
  i18n/
    index.ts                # Настройка языков, сохранение выбора, язык HTML
    i18next.d.ts            # Типы и подсказки для ключей переводов
    locales/
      ru.json               # Русские тексты
      en.json               # Английские тексты
  styles/
    index.css               # Tailwind, переменные дизайн-системы и общие стили
  main.tsx                  # Точка входа: подключает переводы, стили и React
index.html                  # HTML-документ, в котором React показывает приложение
vite.config.ts              # Плагины React и Tailwind для Vite
tsconfig*.json              # Настройки TypeScript
.oxlintrc.json              # Настройки проверки кода
package.json                # Название проекта, команды и зависимости
package-lock.json           # Точные версии всего дерева зависимостей
.gitignore                  # Файлы, которые не нужно добавлять в Git
```

`node_modules/` содержит установленные пакеты, а `dist/` — результат сборки. Эти папки создаются командами npm и исключены из Git. Новые компоненты размещайте в `components/`, содержимое страниц — в `pages/`. Создавать пустые папки про запас не требуется.

## Как работать с переводами

1. Добавьте одинаковый ключ в `src/i18n/locales/ru.json` и `src/i18n/locales/en.json`.
2. В компоненте получите функцию перевода и используйте ключ:

```tsx
import { useTranslation } from 'react-i18next'

export function Example() {
  const { t } = useTranslation()
  return <p>{t('home.description')}</p>
}
```

При первом открытии используется русский язык. Кнопки RU / EN переключают тексты без перезагрузки. Выбор хранится в `localStorage` под ключом `multiwheel.language`; если браузер запрещает хранилище, переключение всё равно работает в текущей вкладке. При смене языка также обновляются атрибут `<html lang>` и описание страницы.

Переводы входят в сборку и не требуют сервера или внешнего сервиса. Проверка ключей TypeScript опирается на русский словарь. Следите, чтобы английский словарь содержал те же ключи: при отсутствии перевода i18next использует русский вариант.

## Базовая дизайн-система

Цвета задаются в `:root` файла `src/styles/index.css`:

| Переменная | Назначение |
| --- | --- |
| `--background` | Основной фон: `#09090B`. |
| `--surface` | Фон компонентов: `#18181F`. |
| `--accent` | Фирменный акцент: `#8B5CF6`. |
| `--text-primary` | Основной текст: `#FAFAFA`. |
| `--text-secondary` | Второстепенный текст: `#A1A1AA`. |
| `--border` | Цвет границ, вычисляется из основного цвета текста. |

В блоке `@theme inline` переменные связаны с классами Tailwind: например, `bg-background`, `bg-surface`, `text-secondary`, `border-border`. Чтобы изменить палитру всего сайта, достаточно поменять значения в `:root`. Здесь же находятся радиус элементов `--control-radius` и максимальная ширина содержимого `--site-width`. Класс `site-container` задаёт общую ширину и боковые отступы шапки и страницы.

Пункты будущих разделов пока выводятся обычным текстом с пометкой «Скоро»: ссылок на отсутствующие секции нет. Кнопка скачивания имеет атрибут `disabled` и видимое пояснение. Временная иконка логотипа — `Aperture` из уже установленного Lucide React.

## Главный экран и демонстрация колеса

`HeroSection.tsx` располагает текст и иллюстрацию в две колонки начиная с ширины 1024 px. На меньших экранах колесо находится под текстом. Тексты хранятся в блоке `hero` обоих словарей.

`WheelPreview.tsx` хранит ID выбранного профиля, показывает переключатель и управляет переходом Motion. Колесо рисуется одним общим компонентом для всех профилей. В каждом из текущих четырёх профилей восемь условных действий.

- `features/wheel/wheelActions.ts` содержит тип `WheelAction` (ID, ключ перевода, иконка) и исходные действия Windows. Их переводы находятся в `hero.wheel.actions`.
- `features/wheel/wheelProfiles.ts` содержит тип `WheelProfile` и массив `wheelProfiles`. Каждый профиль имеет уникальный ID, ключи названия и описания, иконку и массив действий. TypeScript проверяет ключи переводов и типы иконок.
- `features/wheel/ProfileSwitcher.tsx` показывает кнопки с `aria-pressed`, поддерживает обычные Tab, Enter и пробел. На узких экранах кнопки располагаются в два ряда. Переключатель автоматически строится из конфигураций.
- `features/wheel/ProfileWheel.tsx` переводит действия профиля и связывает хук взаимодействия с `WheelView`. Компонент получает `key` по ID профиля, поэтому при смене профиля заново создаётся состояние: без выбранного сектора, с логотипом в центре и первой остановкой Tab. Во время ухода старое колесо скрыто от вспомогательных технологий и не принимает ввод. Переход не меняет размеры области SVG.
- `features/wheel/useWheelInteraction.ts` отвечает за наведение, фокус, нажатия и клавиши. Он принимает список ID и не зависит от количества секторов, иконок, переводов или размеров колеса.
- `features/wheel/wheelGeometry.ts` хранит размеры в координатах SVG. Углы рассчитываются из количества действий; при восьми элементах исходная геометрия сохраняется.
- `features/wheel/WheelView.tsx` рисует SVG, центр и плавные переходы Motion. Для нового дизайна можно изменить этот файл и геометрию, сохранив данные и логику управления.

Наведите указатель на сектор, чтобы подсветить его и увидеть название в центре. При уходе указателя возвращается действие с фокусом или логотип, если фокуса нет. Нажатие, включая касание, фокусирует сектор; выбор сохраняется до ухода фокуса, нажатия вне колеса или Escape. Действия только показываются в демонстрации: копирование, вставка, поиск и другие команды не выполняются.

Для клавиатуры предусмотрена одна остановка Tab на всём колесе. Стрелки переключают секторы по кругу, Home и End выбирают крайние, Enter и пробел показывают действие, Escape возвращает логотип. Tab и Shift+Tab выводят фокус из колеса. При фокусе с клавиатуры видна пунктирная граница сектора.

Неподвижная область попадания отделена от увеличивающегося SVG-слоя, поэтому граница наведения не двигается вместе с анимацией. Цвета берутся из CSS-переменных, свечение задаётся классом `wheel-preview-glow` в общих стилях. При `prefers-reduced-motion: reduce` увеличение отключено, цвета и подписи переключаются без анимации. Постоянных анимаций у колеса нет.

## Как добавить профиль приложения

1. Добавьте в оба словаря `src/i18n/locales/ru.json` и `en.json` блок `hero.wheel.profiles.<id>` с полями `name`, `description` и `actions`. Описание должно явно называть профиль концептуальным примером. Названия действий делайте короткими, чтобы они помещались в центр колеса.
2. В `src/features/wheel/wheelProfiles.ts` импортируйте нужные иконки Lucide и добавьте объект в `wheelProfiles`: уникальный `id`, ключи `nameKey` и `descriptionKey`, `icon` и восемь элементов `actions`. Для каждого действия укажите уникальный внутри профиля `id`, `labelKey` и `icon`. ID действий могут повторяться в разных профилях: состояние всё равно сбрасывается при переключении.
3. Выполните `npm run build`, проверьте новый профиль на обоих языках, выбор сектора, сброс при смене профиля и узкий экран.

Менять компоненты колеса и переключателя не требуется. Порядок объектов в массиве задаёт порядок кнопок. Геометрия и логика взаимодействия продолжают учитывать длину массива действий, сохраняя возможность будущих изменений дизайна и состава меню.

## Ручная проверка

После запуска проверьте: русский язык при первом открытии, переключение на английский, сохранение языка после обновления страницы и возврат на русский. Кнопки должны работать с клавиатуры (`Tab`, затем `Enter` или `Пробел`). После изменений выполните `npm run build`.

Для колеса проверьте наведение на каждый сектор, возврат логотипа после ухода указателя, выбор нажатием и сброс нажатием вне колеса. С клавиатуры проверьте вход и выход через Tab, циклические переходы стрелками, Home/End, Enter, пробел и Escape. На узком экране колесо должно помещаться по ширине, а при смене языка должны переводиться названия действий, доступные подписи и подсказки.

Для профилей проверьте все четыре кнопки: наборы действий должны отличаться, описание должно переводиться, а центр после переключения должен показывать логотип. Проверьте также быстрые повторные переключения, Enter и пробел на кнопках профилей и перенос переключателя в два ряда на мобильном экране.
